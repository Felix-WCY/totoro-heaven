## 2. ⚠️ 结论翻转：租户域**不是**另一套后端

### 2.1 我的错误探测

第一次探测**没发 `Authorization` 头**，得到：

| 主机 | `getSunRunSchoolList` | `getSunRunFirstConfiguration` |
| --- | --- | --- |
| `wxxcx.xtotoro.com` | 200 | 200 |
| `yanggpa.ustl.edu.cn` 等 5 个 | **401 / 503** | **401 / 503** |

据此我下了"另一套后端"的结论，还撤回了一次放宽。**这个结论是错的。**

### 2.2 正确探测（补上 `Authorization: Bearer null`）

本项目代理**始终**会补这个头（`server/api/mp/[...slug].ts` 文件头写明：鉴权过滤器只检查头是否存在，
不带 → 401）。补上之后：

| 主机 | `getSunRunSchoolList` | `getSunRunFirstConfiguration` |
| --- | --- | --- |
| `wxxcx.xtotoro.com` | 200 | 200 |
| `yanggpa.ustl.edu.cn` | 503（该端点只在共享域提供） | **200 ✅** |
| `sunnysport.zjyc.edu.cn` | 503 | **200 ✅** |
| `shtc.jscn.edu.cn` | 503 | **200 ✅** |
| `sunrun.jsfpc.edu.cn` | 503 | **200 ✅** |
| `zhygp.just.edu.cn` | 503 | **200 ✅** |

### 2.3 逐端点对比（共享域 vs 辽宁科技大学，都带 `Bearer null`）

| 端点 | 共享域 | 辽宁科技大学 |
| --- | --- | --- |
| 学生档案 `GetStudentInfoByToken` | 200，`status=-998` | 200，`status=-998`（**完全一致**） |
| 任务纸 `getSunrunPaper` | 200 | 200 |
| 学期列表 `getTermList` | 200 | 200 |
| 任务约束 `getSunrunArch` | 200 | 200 |
| 摄像头杆 `getCameraConfig` | 200 | 200 |
| 开场人脸配置 `selectSunRunStartConfiguration` | 200 | 200 |
| 随机抽查配置 `selectSunRunRandomConfiguration` | 200 | 200 |

**⇒ 13 所走同一套 API。租户域只是网关更严（要求带头），不是另一套后端。**

### 2.4 为什么 `getSunRunSchoolList` 在租户域 503

那是"**全局学校列表**"端点，只在共享域提供 —— 本来就不该在租户域调用。
程序的实际顺序是：**先在共享域查列表**（`resolveSchoolBaseUrl` 不传 `baseUrl`）拿到该校 `domainUrl`，
再用租户域调后续接口 ⇒ 不受影响。

### 2.5 代码现状

- 客户端判据：`isKnownSchoolDomain()`（共享域 ∪ 5 个租户域），未知域仍拒绝；
- 服务端上游白名单：`ALLOWED_EXACT_HOSTS` 含 5 个租户域 + `*.xtotoro.com` 后缀；
- 唯一来源：`utils/mp/schoolGate.ts` 的 `KNOWN_SCHOOL_DOMAINS`。

## 4. 三个风控开关：**只有南航有记录**

`utils/mp/schoolGate.ts` 的 `VERIFIED_SCHOOLS` 里**只有一条**：

```ts
{ schoolCode: '98765', knownSwitches: { sunrunStartFace: '0', sunrunPointRandom: '0', cameraFlag: false } }
```

其余 12 所**全仓库没有任何开关记录**（已搜索 `src/ utils/ composables/ server/ tests/ docs/`）。

⚠️ **「共享域学校都没开人脸」没有任何依据。** 作者的设计是：

> 支持范围 = 条件式：① 共享域 **且** ② **运行时**读到该校未开启三类风控

这是**且**。运行时读不到开关 → 也拒绝（`switches_unknown`）。

### 为什么免 token 查不到

58 个端点里：**免鉴权 8 个**（全是登录注册用）、**需 token 50 个**（任务/线路/提交/判分/风控全部）。

试过两个风控配置端点（`selectSunRunStartConfiguration`、`selectSunRunRandomConfiguration`）：
**不带真实 token 时一律 `200` + `obj: {}`** —— 查不出任何东西。

**⇒ 一个真实学生的 token 是唯一入口，没有变通。**

## 5. ⚠️ 另一道门：学生用的是小程序还是 App

这条与学校无关，但同样会让人"买了用不了"。

| 形态 | 支持情况 |
| --- | --- |
| **微信小程序** | ✅ 支持（本工具只为小程序后端实现） |
| **独立 App** | ❌ **完全不支持** |

原因有两条：

1. 「一键获取 TOKEN」只扫 `WeChatAppEx.exe`（PC 微信小程序宿主进程）的内存 ——
   用 App 的人电脑上**没有这个进程**，永远扫不到；
2. App 通道的代码在 **2026-09-11** 就被删除了（commit `524cd5f`：「仓库彻底转为纯微信小程序后端线，
   删除旧 App 后端全部源码」，删掉的是 `src/wrappers/TotoroApiWrapper.ts`）；
   `NOTICE` 记录：那批旧 App 代码衍生自 AGPL 项目，所以不能再用。

**应对**：买家来问时**先问一句「你用的是小程序还是 App」**。
有人说「我们都是用 App」时，让他去微信里搜小程序 —— 厂商给该校开了小程序租户，通常能搜到。

## 7. 验证协议（拿到一个 token 即可，约 10 分钟）

### 7.1 需要什么

该校在读学生的 **token**（只读），或**两张截图**（更推荐，避免持有他人凭证）：

1. 工作台「会话与真实 token」卡片 → 学校名 + **三个开关**
2. 「任务与约束」卡片 → 里程/配速/时间窗/围栏

### 7.2 验什么

| 步 | 操作 | 通过标准 | 不通过的含义 |
| --- | --- | --- | --- |
| 1 | 输入 token（或看截图）→ 读取真实账号与任务 | 读出学校名/任务列表 | 报错 → 接口不兼容 |
| 2 | 看「任务与约束」 | 里程/配速/时间窗/围栏都能显示 | 字段缺失 → 任务结构不同 |
| 3 | 看三个开关 | 全部「关闭」 | **任一「开启」→ 该校永久不支持**（作者红线） |
| 4 | 真跑一次最短线路 | 「记录」页判「有效」 | 判无效 → 判分口径不同，需调参 |

### 7.3 什么时候才能写 `verified: true`

**只有第 4 步通过。** 前 3 步通过只能说明"能跑"，不能说明"跑完算分"。
