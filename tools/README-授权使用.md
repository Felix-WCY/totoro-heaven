# 授权使用说明

> 📘 本文件是**签发侧快速上手**。完整的「使用 / 签发 / 维护 / 排错」手册 ——
> 含**十条红线**、数据目录说明、排错对照表、以及**给 AI 助手的硬约束** ——
> 见 [`docs/授权门禁-完整说明.md`](../docs/授权门禁-完整说明.md)。

本文件说明本项目**授权门禁**的完整用法。面向两类读者：

- **使用者**：拿到本软件、需要激活 → 看「一、二」；
- **签发者**（持有私钥的人）：需要给别人发授权 → 看「三、四、五」。

---

## 一、原理（一分钟看懂）

```
  签发者（唯一持有私钥）              使用者（客户端只嵌公钥）
        │                                    │
        │  ① 使用者把「机器码」报给签发者        │
        │  ◄─────────────────────────────────┤
        │                                    │
        │  ② 签发者用私钥签出一张「授权证书」    │
        ├───────────────────────────────────►│
        │                                    │  ③ 粘贴证书 → 激活
        │                                    │     本机验签，不联网
```

- 客户端**只内嵌公钥**：拿不到私钥就无法伪造证书；
- 证书里的机器码**与本机绑定**：转发给别人也激活不了；
- 验签**完全在本机完成**（约 50 微秒，结果缓存 5 分钟）⇒ **激活一次后可离线使用**，不依赖任何服务器。

---

## 二、使用者：怎么激活

1. 启动程序，打开顶栏「**授权**」页；
2. 复制页面上的「**本机机器码**」，形如 `A1B2-C3D4-E5F6-0718`；
3. 把机器码发给**给你软件的人**（授权证书签发者）；
4. 把收到的**整段授权证书**粘贴回「授权」页，点「**激活**」。

> 证书是一长串字符，从聊天窗口复制常带换行和空格 —— **不影响**，程序会自动忽略。
> 复制时请**整段复制**，漏字会被判为「证书格式不正确」。

激活成功后，页面会显示授权对象、正常到期时间与离线宽限至。
到期前重新拿一张新证书粘回即可续期；换机器需要**用新机器码重新签发**。

### 开发模式与打包版的差异（⚠️ 最容易踩的坑）

| 场景 | 是否校验授权 |
| --- | --- |
| `npm run dev` | **不校验**（开发旁路，便于调试） |
| `npm run sea` 打包出的 EXE | **强制校验** |

想在本机按**正式版口径**自测，启动前设环境变量：

```powershell
$env:TOTORO_LICENSE_STRICT = "1"; npm run dev
```

## 三、签发者：一次性准备

签发需要**私钥**。私钥**不在仓库里**（`tools/keys/` 已被 `.gitignore` 排除），只在签发者本机。

### 全新开始（项目里还没有密钥对）

```powershell
node tools/license-keygen.ts
```

产出两样东西：

| 文件 | 内容 | 去处 |
| --- | --- | --- |
| `tools/keys/license-private.pem` | 🔴 **私钥** | **只留本机**，离线备份，绝不外发、绝不入库 |
| `server/utils/license/publicKey.ts` | 公钥（自动写入） | **必须进仓库**，会被打进 EXE |

### 项目已有密钥对（大多数情况）

直接看 `server/utils/license/publicKey.ts` 里是否已有公钥：
- **有** ⇒ 说明密钥对已存在，**去找签发者要私钥**（或由他签发），**不要**重新生成；
- **没有**（空串）⇒ 按上面「全新开始」生成。

## 四、签发者：给别人发授权

对方把机器码发来后：

```powershell
node tools/license-issue.ts --machine "A1B2-C3D4-E5F6-0718" --sub "张三" --days 365
```

把输出的**整段证书**发给对方即可。

### 参数表

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--machine` | ✅ | 机器码。**让对方直接复制**，别手抄；大小写与连字符会被自动归一 |
| `--sub` | ✅ | 授权对象（客户名/备注），会显示在对方的「授权」页上 |
| `--days` | | 有效天数，默认 **365**。到期后再给 **14 天离线宽限** |
| `--features` | | 功能位，默认 `pro`（当前仅记录与展示，不做差异化限制） |
| `--lic` | | 许可证编号，默认自动生成 `TH-XXXX-XXXX` |

### 签发台账

每次签发都会**追加一行**到 `tools/keys/issued.jsonl`（含时间、编号、对象、机器码、证书），
用于对账与重发。该目录同样不入库（含客户信息）。

## 五、🔴 三条必须遵守的规矩

### 1. 私钥必须离线备份

```
tools/keys/license-private.pem
```

- **丢了** ⇒ 已发出的证书**全部作废**（换公钥就得给所有人重发），且再也签不出新证书；
- **泄漏了** ⇒ 别人能自己签发证书，整套门禁失效。

请复制到 U 盘或密码管理器。

### 2. 整个项目**只应存在一把密钥对**

`node tools/license-keygen.ts --force` 会**更换密钥对**，此时：

- `publicKey.ts` 里的公钥被换掉 ⇒ **已发出的所有证书立即全部作废**；
- 所有使用者都必须重新激活。

所以：**不要**为了"自己也能签发"而各生成一把 —— 两个人各持一把密钥，会互相签出对方验不过的证书。
需要多人签发时，应当**共享同一把私钥**（并接受相应的泄漏风险），或指定唯一签发者。

### 3. 不要把私钥、台账、证书提交到仓库

`.gitignore` 已屏蔽 `/tools/keys/`。提交前可用下面这条自检：

```powershell
git check-ignore -v --no-index -- tools/keys/issued.jsonl tools/keys/license-private.pem
```

两个文件都必须命中（输出里应有 `.gitignore:…:/tools/keys/`）。

## 六、日常操作速查

| 想做的事 | 怎么做 |
| --- | --- |
| 续期 | 用**同一个机器码**再签一张（可改 `--days`），对方重新粘贴激活 |
| 换机器 / 重装系统 | 新机器上取**新机器码** → 重新签发一张 |
| 对方解绑 | 「授权」页点「**解除本机授权**」（换机前先解绑较干净） |
| 查授权状态 | 「授权」页，或 `GET /api/local/license/status` |
| 查谁拿了什么 | `tools/keys/issued.jsonl` |
| 作废某张证书 | 当前为**离线签发**模型，**无法远程吊销**；只能等它到期（宽限期过后自动失效） |

> ⚠️ **无法远程吊销**是离线模型的固有代价（换来的是"不依赖服务器、可长期离线"）。
> 需要实时吊销时，得另建一个在线激活接口（属于后续工作，本项目当前未实现）。

## 七、排查

| 现象 | 原因与处理 |
| --- | --- |
| 「本程序尚未配置许可证公钥」 | `publicKey.ts` 里公钥为空 ⇒ 签发者还没跑 `license-keygen.ts`，或构建时用错了源码 |
| 「证书格式不正确」 | 复制不完整（漏字/截断）⇒ 让对方**整段重新复制** |
| 「证书签名无效」 | 证书被改动，或不是同一把密钥签发的 ⇒ 确认签发者用的是项目唯一那把私钥 |
| 「证书与本机机器码不匹配」 | 这是发给**另一台机器**的证书 ⇒ 用本机机器码重新签发 |
| 「授权已过期」 | 已超出离线宽限 ⇒ 重新签发一张 |
| 「机器码无法持久保存」 | 授权目录不可写 ⇒ 检查 `%LOCALAPPDATA%\totoro-heaven` 的权限 |

授权数据目录（含证书与实例 ID）：`%LOCALAPPDATA%\totoro-heaven`
（可用环境变量 `TOTORO_LICENSE_DIR` 覆盖，便于测试）
